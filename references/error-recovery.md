# 错误恢复策略

当某个阶段执行失败或被阻塞时，遵循以下恢复规则：

## 阶段1失败（目标无法确认）
- 暂停全部验收，向用户追问缺失信息
- 不得跳过进入阶段2

## 阶段2检查项失败（如 SKILL.md 缺失、脚本不存在）
- 记录失败项，将对应功能标记为 `blocked`
- 其余不依赖该失败项的检查子项继续执行
- 若 SKILL.md 整体缺失，整个阶段2标记为 `blocked`，直接跳到阶段3尝试平台发现

## 阶段3失败（平台命令执行失败）
- 先确认 YonClaw 服务是否运行，若未运行则提示用户启动后重试
- 若 `yonclaw info` 返回空但 `yonclaw list` 可见，记录平台发现不一致，尝试用 list 结果推断路径
- 若三条命令全部失败，阶段3标记为 `blocked`，阶段4可仅基于静态证据执行受限验收（结论必须降级）

## 阶段4失败（动态用例执行异常）
- 单条用例超时或报错：记录错误信息，该用例标记为 `blocked`，其余用例继续
- 全部动态用例不可执行：阶段4标记为 `blocked`，验收结论最高为 `有条件通过`
- 写操作用例执行后产生脏数据：立即回查确认影响范围，记录回查结果；不得在回查完成前输出结论

## 阶段5失败（覆盖评估发现重大缺口）
- 回退到阶段3a补充功能清单，重新评估覆盖矩阵

## 阶段6失败（报告生成或校验失败）
- Excel 生成失败：降级为 Markdown 报告，记录降级原因
- Markdown 校验失败：按校验器输出逐项修正，最多重试 3 次；3 次仍失败则报告标记为 `invalid`，结论降级
- validate_checkpoints.mjs 或 validate_checkpoints.py 失败：按错误信息修正对应阶段产物，重新校验；不得绕过校验
- validate_excel_report.py 失败：按错误信息补齐检查点自检、修正覆盖位置、回写明细、重算汇总，重新校验

## 环境不可用（认证失败、服务宕机）
- 当前阶段标记为 `blocked`，记录阻塞原因和恢复条件
- 已完成阶段的结果保留，不回退

## 恢复记录要求
所有恢复动作必须在报告中记录：`原失败点 | 恢复动作 | 恢复结果 | 对结论的影响`。
